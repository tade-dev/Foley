# Foley — Build Design (weekend build, Nov 14–16 2026)

This document is the design for the Foley build. The full product spec is the
handoff at `docs/handoff/HANDOFF.md` (screens in `docs/handoff/design/`,
tokens in `docs/handoff/tokens.json`). **Read the handoff first.** This file
records the decisions made on top of it for this build, the order of work and
the acceptance bar. Where the two disagree, this file wins.

## Intent

A portfolio-grade native iOS soundboard: describe a scene, get 4–6
AI-generated sound pads, tap/loop/layer/mix them, record a mix and share it.
Motion, audio-reactive UI and polish matter as much as features. It is posted
publicly (GitHub + demo video) on Monday Nov 17, so the repo must build and
play on a fresh clone with no keys.

## Goals, non-goals, anti-goals

**Goals (all in scope):** the nine screens in the handoff, the pad state
machine, live audio-reactive glow, the word-to-pad hero flight, orbit mixer,
pad sheet with regenerate, recording to .m4a, 9:16 share video, scene
library, two bundled demo scenes, README with demo GIF and proxy setup steps.

**Non-goals (v1):** accounts, cloud sync, iPad layout, remixing other
people's scenes (Share scene = share sheet with a text summary), light mode.

**Anti-goals (would make it a failure even if it "works"):**
- An API key or secret anywhere in the app bundle, repo or git history.
- A fresh clone that launches to silence or an empty screen.
- Jank: dropped frames with six pads looping, or animations that run on a
  fixed timer instead of real audio levels.
- Generic-looking UI. The orb and the dark palette in the handoff are the
  look; no stock list-and-form screens.

## Interaction additions

On top of the handoff's motion table:

1. **Pad press feel** — pads scale to 0.96 with a spring and the orb lags the card by ~40 ms (secondary motion), so a tap feels physical.
2. **Orb glow bleeds onto the board** — the board's mesh gradient tints toward the currently playing pads' tints (weighted by level), so the whole screen "breathes" with the mix.
3. **Chip-to-composer typing** uses the handoff's 30 chars/s type-in with a caret; the orb on Home brightens as text length grows.
4. **Transport play/stop** morphs the glyph with `contentTransition(.symbolEffect(.replace))` and the dock gets a brief glass highlight sweep on press.
5. **Orbit mixer** snaps nodes gently back inside the outer ring with a rubber-band when dragged out; releasing a node gives a small overshoot spring.
6. **Library cards** parallax their orb row slightly with scroll offset (`scrollTransition`), in addition to the scale/fade in the handoff.
7. **Generating screen progress bar** fills with a spring per landed pad, not linearly.
8. **Mix saved** screen: the hero card's waveform draws in (handoff) and the orb row does a one-time staggered pop.

Rules from the handoff still apply: springs everywhere, ≤ ~10 haptics/s, one hero moment (word-to-pad flight), one living system (level-driven glow).

## Architecture (as in the handoff, with the service boundary named)

```
SwiftUI views
  └─ SceneStore (@Observable, MainActor)       transient pad status, playing set, current scene
       ├─ GenerationService (protocol)         buildScene(prompt) / generate(pad) / regenerate
       │     ├─ MockGenerationService          Phase A: simulated latency + failures, bundled audio
       │     └─ LiveGenerationService          Phase B: Worker /scene + /sound, concurrency 3, retry, cache
       ├─ AudioCache                            Application Support files keyed by sha256(spec)
       ├─ AudioEngine (@Observable, MainActor)  AVAudioEngine, one player per pad, taps → levels @60 Hz, recording
       ├─ MixRenderer                           .m4a → 9:16 .mp4 (AVAssetWriter + CoreGraphics)
       └─ SwiftData (Scene, Pad, Mix)
```

A `Mix` model is added (not in the handoff): `id`, `scene` relationship,
`fileName`, `duration`, `createdAt`, `envelopeFileName`. Library rows show
"N mixes" from it.

## Phases and order

**Phase A — client (target: Saturday night).**
1. Project setup: iOS 26 target, Swift 6, folder layout, Theme + Models from the handoff compiling, placeholder demo audio script.
2. AudioEngine with the placeholder sounds: load, toggle, loop, one-shot, volume/pan, levels, loop progress, recording.
3. Components in previews: SoundOrb, PadView (5 states), LoopRing, MiniMeter, MasterMeter, chips, Composer, TransportDock, RecPill, WaveformView, KeywordText, OrbitNode, SceneCard, ShareRow.
4. SceneStore + MockGenerationService + demo seeding.
5. Screens: Library (09) → Home (01) → Typing (02) → Generating (03, with the hero flight) → Board/Playing (04–05) → Orbit (06) → Pad sheet (07) → Mix saved (08).
6. Recording + MixRenderer + share sheet.
7. Polish: glass, interaction additions, Reduce Motion, VoiceOver, icon.

**Phase B — backend (target: Sunday).**
8. Worker: `/scene` on OpenAI structured output, `/sound` on ElevenLabs, rate limit, `wrangler.toml`, deploy; `proxy/README`.
9. LiveGenerationService (concurrency 3, 429 backoff, cache) wired behind a build setting / `Secrets.xcconfig`-free `ProxyConfig` (the Worker URL is not a secret and lives in `Info.plist`).
10. Generate the real demo sounds with the owner's key; replace placeholders.
11. README, demo GIF, final QA on a fresh clone.

## Acceptance (from the handoff, adjusted for simulator-only)

- Fresh clone builds in Xcode 27 and plays both demo scenes with no keys.
- A typed scene produces 4–6 playable pads in under ~20 s.
- Regenerating the same spec never calls the API twice.
- 6 pads looping together stay smooth on the simulator with live glow.
- Failed pads show Retry and recover in place.
- No key or secret in the bundle, repo or history.
- Recorded mix exports as .m4a and as a 9:16 video; both open from the share sheet.
- Every screen usable with VoiceOver and Reduce Motion.
- README with demo GIF, architecture diagram and proxy setup.
